# SupportFlow

Консольная система обработки обращений в службу поддержки на чистой Java 21, без фреймворков. Обращения заводятся, назначаются на сотрудников, проходят по жизненному циклу с контролем допустимых переходов статусов и обсуждаются в комментариях.

## Какие задачи решает

Сценарий команды поддержки:

Сотрудник заводит обращение: тема, описание, приоритет.
Обращение попадает в очередь, где срочные идут выше остальных.
Исполнитель берёт его в работу, оставляет комментарии.
Обращение решается и закрывается. Если проблема вернулась, его можно открыть повторно.

Система следит, чтобы этот процесс не нарушался: нельзя закрыть обращение, которое ещё не брали в работу, и нельзя комментировать закрытое.

### Возможности
- Создание обращения с темой, описанием и приоритетом (низкий, средний, высокий, критический).
- Список обращений с фильтром по статусу. Сортировка: сначала самые срочные, внутри приоритета самые старые.
- Карточка обращения: автор, исполнитель, даты, описание, комментарии и список статусов, в которые можно перейти.
- Смена статуса с проверкой допустимых переходов.
- Назначение исполнителя.
- Комментарии с автором и временем.
  
## Жизненный цикл обращения

```
NEW ──► IN_PROGRESS ──► RESOLVED ──► CLOSED
 │         │   ▲            │
 │         ▼   │            └──► REOPENED ──► IN_PROGRESS
 │   WAITING_FOR_CUSTOMER ──► RESOLVED
 └──► CLOSED
```


### Правила, которые проверяются в модели:

Закрытому обращению нельзя назначить исполнителя, добавить комментарий или изменить приоритет.
Тема обращения и текст комментария не могут быть пустыми.
У обращения и комментария всегда есть автор.

### Быстрый старт

Нужны JDK 21 и Maven 3.9 или новее.

```bash
mvn package
java -jar target/supportflow-1.0.0.jar
```

Запуск тестов: mvn test.

В программе заранее заведены три сотрудника: Анна Смирнова, Иван Петров и Мария Орлова. Добавление сотрудников через консоль пока не реализовано, но сервис умеет это делать (registerEmployee).

Значения после двоеточия вводит пользователь.

 SupportFlow: система обработки обращений:
```
1. Создать обращение
2. Список обращений
3. Показать обращение
4. Сменить статус
5. Назначить исполнителя
6. Добавить комментарий
0. Выход

  1 — Анна Смирнова

```

```
Новый статус (номер, имя или название): RESOLVED
Ошибка: Переход из «Новое» в «Решено» недопустим
```

### Архитектура
```
src/main/java/com/supportflow/
├── Main.java                      точка входа, ручная сборка зависимостей
├── model/
│   ├── Ticket.java                обращение и его правила
│   ├── Employee.java
│   ├── Comment.java               record, неизменяемый
│   ├── TicketStatus.java          статусы и допустимые переходы
│   └── Priority.java
├── repository/
│   ├── TicketRepository.java      хранилище в памяти
│   └── EmployeeRepository.java
├── service/
│   ├── TicketService.java         интерфейс сценариев
│   └── TicketServiceImpl.java
├── exception/
│   ├── TicketNotFoundException.java
│   └── InvalidStatusTransitionException.java
└── ui/
    └── ConsoleApp.java            ввод, вывод, перехват ошибок
```

Зависимости направлены в одну сторону: ui → service → repository → model. Консоль ничего не знает про хранилище, а модель ничего не знает про консоль.

### Тесты:

JUnit 5. Покрыто:

- Статусы: финальный статус не имеет переходов, ни один статус не переходит сам в себя, проверены основной сценарий и повторное открытие.
- Сервис: создание обращения, полный жизненный цикл, недопустимый переход (статус при этом не меняется), закрытое обращение нельзя комментировать и переназначать, порядок комментариев, фильтр по статусу, сортировка по приоритету.
- Консоль: создание и просмотр обращения, ошибка при недопустимом переходе, ввод не числа, конец ввода.

Эта версия служит основой для полноценного backend-проекта.
